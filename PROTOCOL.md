# robot-play protocol (overnight pilot, v1)

This document is written **before** the paid experiments run. It fixes what is compared, how many runs there
are, what counts as success, and which results would falsify each claim. Anything that deviates from it
in the results is listed in `RESULTS.md` under "Deviations".

## 1. Questions and pre-stated claims

Setting: an LLM orchestrates a simulated Franka Panda through skill tools (pick, place, move, ...) built
on IK and collision-checked motion planning. No weights are trained. The environment has **hidden physical
quirks** (section 3). Between episodes the agent may update a small memory.

| ID | Question | Primary measure | Claim is supported only if |
|---|---|---|---|
| Q1 | Does in-context experience raise success on a quirky task? | Held-out success rate, memory (notebook or replay) vs none, same model, paired by task and seed | Difference > 0 with a 95% cluster-bootstrap CI (resampling runs) excluding 0, **and** no comparable gain in the no-quirk control environment |
| Q2 | Does experience make the agent faster/cheaper per success? | Sim seconds, tool calls and dollars per successful episode, held-out | Same test as Q1 on the ratio |
| Q3 | Can a cheap model with experience come within a stated margin of a frontier model's first try? | Held-out success of cheap+notebook vs frontier no-memory, pooled over the 3 tasks | The 95% CI of (frontier - cheap+notebook) lies below **+10 percentage points**. Otherwise we only report the gap with its interval, and do not say "matches" |
| Q4 | Does experience help recovery from a disturbance? | Success after a mid-episode disturbance, frozen-notebook agent vs fresh agent, same seeds | CI of the paired difference excludes 0 |

Cost in Q3 includes **all** calls the cheap model made (practice, memory writing, evaluation).

Null results are reported. Every number in the README comes from `results/` and is regenerated by `make report`.

## 2. Environments

- Robot: Franka Panda (MuJoCo Menagerie, pinned). The SO-101 is future work; it is not in this pilot.
- MuJoCo is pinned to the installed `4.0.1`; Python deps are pinned by `uv.lock`. Physics timestep 2 ms.
- Three tasks (the third was `bottle` in the first draft and is now `flasks`, see the changelog), each with one physical quirk that is **fixed across all seeds** (the poses and distractor
  positions are resampled each episode, the quirk is not):

| Task | Goal (success predicate computed from simulator state) | Quirk (physical) | Control environment (no quirk) |
|---|---|---|---|
| `stack` | cubes red, green, blue stacked in that order, each within 12 mm of the stack axis, stable for 1 s | The green cube weighs 250 g (the others 50 g) and has lower friction (0.5 against 0.9). A `normal` squeeze cannot hold it; `firm` can, and `slow` keeps it from tilting on release | Green cube 50 g, friction 0.9 |
| `bins` | every cube in the bin that matches its colour, resting on the bin floor | The bins have 12 cm walls. The planner reports `arm/hand would touch bin_*_wall*` unless the cube is released from about 12 cm up or higher | 1.5 cm walls |
| `flasks` | both flasks upright (< 10 deg tilt) within 3 cm of their rings, standing on the floor | Each flask has a 10 cm wide, 7 cm tall base under a 4 cm wide neck. The hand opens 8 cm, so fingers land on the base and the descent stops short. Grabbing the neck (`grasp_height` about 0.9) works | Plain cylinder of the same height (5 cm wide) |

- The collision model used by the planner is **identical** in quirk and control scenes: the skill layer never
  routes around a quirk for the agent.
- Scene poses per episode come from `seed`; held-out evaluation uses seeds that practice never uses.

## 3. Tools (what the agent can do and see)

`observe()`, `pick(object, grasp_height, speed, grip_level, yaw_offset, lift_height)`,
`place(target, release_height, speed, settle_time)`, `move_to(x, y, z, speed)`, `open_gripper()`,
`close_gripper()`, `home()`, `done()`.

- Parameters have **neutral descriptions and defaults**. Several are decoys with no effect in a given task,
  so the agent must find out which ones matter. No parameter name or description mentions a quirk.
- Tools return **measured facts only**: whether the object is between the fingers (finger width), the object
  height change during the lift, the final object pose, contacts reported by the simulator, and plan/IK
  failures with their raw reason. They never state a cause ("too heavy", "too fast").
- `observe()` returns exact simulator poses (no perception noise in the pilot). A perception bias would be
  a sensor fault, not a physical quirk, and is out of scope.
- **Success is decided only by the simulator** after the agent calls `done()` or runs out of steps
  (30 tool calls). The agent's own claim is logged and its false-success rate is reported.

## 4. Memory conditions (all without training)

| Condition | After each episode the agent gets | Cap |
|---|---|---|
| `none` | nothing carried over | - |
| `notebook` | its own notebook, which it **rewrites** from the episode result (replace, not append) | 600 tokens |
| `replay` | the transcript of its most recent **successful** episode in this task, if any | 1,200 tokens |

Token counts of the added context are logged, and the `none` condition's lower token use is reported as is
(it is not padded). An optional `none+pad` control is run on one task if budget allows.

## 5. Experiment matrix and budget (pilot)

Unit of analysis: a **run** = (model, task, condition, seed) = 12 practice episodes with memory carried over,
followed by **4 held-out evaluation episodes with the memory frozen**.

| Cell | Models | Tasks | Conditions | Seeds | Episodes |
|---|---|---|---|---|---|
| Main | Haiku 5.5, GPT-6 Luna | 3 | none, notebook, replay | 5 | 2x3x3x5x16 = 1,440 |
| Control (no quirk) | same | 3 | none, notebook | 3 | 2x3x2x3x16 = 576 |
| Disturbance (Q4) | same | 3 | frozen notebook vs fresh | 5 | uses the held-out seeds: 2x3x5x4 = 120 extra |
| Frontier first try (Q3) | Fable 5.2, GPT-6 Astra | 3 | none | 10 poses each | 2x3x10 = 60 |
| Frontier + experience | Fable 5.2 | 3 | notebook | 1 | 3x16 = 48 |

- The control and frontier cells only run after the main cell has produced a usable smoke result.
- Hard stops: Anthropic **$90**, OpenAI **$45** (section 6). If the measured cost per episode makes the full
  matrix infeasible, cells are dropped in this order: control seeds, replay, frontier + experience.
- Sampling: provider defaults (Anthropic effort `low`, OpenAI reasoning effort `low`) for every model so that
  differences come from the models and memory, not from tuned settings. Pinned IDs: `claude-haiku-5-5`,
  `claude-fable-5-2`, `gpt-6-luna`, `gpt-6-astra`.
- 8+ worker processes run runs in parallel. Each run is seeded and logs every tool call, observation and token count.

## 6. Spend meter (enforced in code, covered by tests)

1. Before every paid call, the worst-case cost (estimated input tokens plus `max_tokens` output) is
   **reserved** against the provider's cap under a cross-process file lock. A call that would exceed the cap is refused.
2. After the call the reservation is replaced by the real cost from the response's usage (including
   cached-input and cache-write rates). Retries and failed calls that were billed count.
3. The ledger is a JSONL file on disk that survives restarts, and a `reconcile` command prints per-model totals.
4. Unit tests: a mocked over-budget call is refused; concurrent workers cannot exceed the cap.
5. The council's judge calls run on the user's subscriptions and are **not** part of these caps.

## 7. Validation gates (before any paid run)

1. **Oracle gate:** for each task, a scripted oracle that knows the quirk succeeds in at least 95% of 100
   sampled seeds, and a naive script (default parameters) succeeds in at most 30%. In the control scenes the naive script succeeds in at least 90%.
2. **Dose-response:** success of the naive script as a function of the quirk parameter (cube mass, wall height,
   centre-of-mass height) is plotted, so a null learning curve can be told apart from a quirk that does nothing.
3. **Predicate tests:** positive and negative scripted cases for each success predicate (e.g. unstacked cubes
   must fail), and a test that the agent-visible observation contains no hidden quirk values.
4. **Leakage check:** practice and evaluation seeds are disjoint; the quirk values never appear in prompts,
   observations or tool descriptions.

## 8. Disturbances (Q4)

Applied by physics, not by editing state: (a) *slip*: the gripper is commanded open for 0.15 s after the object
has been lifted 3 cm; (b) *nudge*: a 0.3 s horizontal force of 1.1 times the object's weight, pointing within 45 degrees of the x axis (from the front or back, because a sideways shove is caught by the open fingers), applied the first time the open hand descends next to an object that is not yet grasped. Timing is fixed relative
to events (first lift / first approach), the same for experienced and fresh agents, and the denominator is all
episodes in which the disturbance fired. "Tool failure" and "instruction change" are text injections, so
they are reported separately and are not part of the pilot.

## 9. Related work and the claimed gap

Verified against abstracts or full text (see the README for links):

| Work | What it does | Closest overlap |
|---|---|---|
| RoboARCade (2611.08209) | 22 long-horizon MuJoCo tasks, agents use pose-level MCP tools; one successful demo in context lifts success; reports false success claims | In-context improvement and the false-success finding are theirs. We do not claim them as new |
| WICL / RoboScript (2611.12885) | Rehearses in simulation from one demo, stores a frozen "task memory", 83.4% on RoboTwin 2.0 | Memory learned without gradients |
| GPT-Policy (2609.19138) | VLM with IK-backed pose tools on real robots, context from videos and interaction history, 3 trials per condition | Tool-calling agent and interaction feedback |
| PhysMem (2602.20323) | Frozen VLM planner builds and verifies hypotheses about physical principles at test time | **Closest** on hidden physics plus memory |
| Act-Observe-Rewrite (2603.04466) | LLM rewrites controller code between episodes (robosuite Lift, PickPlaceCan, Stack) | In-context policy learning across episodes |
| PhysCaP (2608.21031) | Code-as-policy agent explores to infer hidden mass/stiffness | Hidden physical properties |
| Voyager, ExpeL, Reflexion, REFLECT, DoReMi, Inner Monologue | Skill/lesson memory and reflection in games or robot planning | Memory mechanisms |
| LangPert, ROBOREPAIR, EmbodiedBench | Perturbation handling, recovery, benchmarks | Disturbances |

**What we claim is new is the combination, not any single axis:** (i) a skill-level tool API with decoy
parameters, so the agent must learn which parameters matter; (ii) physical quirks validated by oracle gates,
dose-response sweeps and no-quirk controls; (iii) learning curves over many episodes with frozen-memory
held-out evaluation and cluster-bootstrap intervals; (iv) disturbance recovery as a function of experience;
(v) a cost-matched cheap-vs-frontier comparison with a pre-stated equivalence margin.


## 10. Changelog (all made before any paid run; none of them used model results)

**v1.1, 16 Nov 2026, after building the environment and playing each task by hand through the tool interface.**

- `bottle` (top-heavy, pinch-height quirk) was replaced by `flasks` (wide base, neck grasp). Reason: with a top-down hand the palm sits 4 cm above the fingertips, so a low pinch on a tall object is physically impossible, and my first top-heavy bottle did not flop even when pinched below its centre of mass because the finger pads resist twisting. The flask quirk is pure geometry and validates cleanly.
- The stack quirk changed from 0.9 kg to 250 g. Reason: the simulated gripper's firm squeeze holds about 300 g; 0.9 kg could not be held by any setting. The gripper's force was also scaled 5 times (the stock model squeezes with about 2 N) so that `light`, `normal` and `firm` are three different forces.
- Contact physics was made stricter (elliptic friction cone, `impratio` 10, finger-pad twisting friction) because held objects crept and pivoted in the pads. Motion uses one smooth profile per move. `place` aims the object, not the hand, and nudges the object into place before releasing.
- `tilt` for a cube counts any face-up orientation as upright, because a cube turned over is still a valid tower piece. Flasks use their own vertical axis.
- The nudge force and direction were tuned on seeds 2000-2029 so that the disturbance gate passes (section 7 check list below). No tuning used any model run.
- Pending, to be decided on practice seeds before the main run and recorded here: the per-task tool call budget (currently 20).

Validation evidence: `results/gate.md` (100 layouts per cell), `results/dose_response.json`, `results/disturbance.md`, `tests/` (pytest), and hand-played transcripts in `docs/TASKS.md`.
